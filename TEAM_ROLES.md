# ProofSkillAI Team Roles

## Team Overview

ProofSkillAI is an evidence-based candidate verification and AI interview platform. The project combines recruiter workflows, resume and GitHub analysis, Proof Cards, voice processing, AI-assisted interviewing, and recruiter-facing evaluation tools.

The team is divided into four ownership areas. Each member owns a primary area while collaborating with the rest of the team during integration, testing, and demonstrations.

| Member | Primary Role |
|---|---|
| Prakarsh Kaushik | AI Architecture and Product Integration Lead |
| Lakshay Kumar | AI/ML, Voice, and Model Integration Engineer |
| Om Upadhyay | UI/UX and Frontend Engineer |
| Titiksha Garg | Backend, Testing, and Deployment Engineer |

---

## 1. Prakarsh Kaushik

### Role

**AI Architecture and Product Integration Lead**

Prakarsh owns the overall AI-driven product direction and ensures that the major ProofSkillAI modules work together as one complete candidate-verification platform.

### Main Responsibilities

- Define the complete ProofSkillAI product workflow.
- Design the AI-led interview experience and interaction model.
- Coordinate the connection between:
  - Resume parsing
  - GitHub analysis
  - Evidence synthesis
  - Proof Card generation
  - Viva interview
  - Recruiter evaluation
- Define how candidate evidence is converted into skills, confidence, gaps, and interview questions.
- Decide which information should be shown to recruiters and which information should remain internal.
- Review the overall architecture and approve cross-module changes.
- Coordinate integration between the local/remote AI model and the Streamlit application.
- Ensure that the final product addresses the evaluation criteria and project requirements.

### Key Deliverables

- Overall system architecture.
- End-to-end candidate and recruiter workflow.
- AI interviewer requirements and behavior.
- Proof Card and evidence-based evaluation strategy.
- Product integration plan.
- Final demonstration flow.
- Technical explanation for judges or evaluators.

### Areas of Ownership

- Product-level AI behavior.
- AI interviewer planning and personalization.
- Cross-module integration.
- Architecture decisions.
- Final product quality and feature prioritization.

### Collaboration

- Works with Lakshay on AI prompts, model behavior, and interview evaluation.
- Works with Om on the candidate-facing Viva experience.
- Works with Titiksha on persistence, authentication, and reliable data flow.

### Presentation Responsibility

Prakarsh presents:

- The project problem and solution.
- Overall architecture.
- AI interviewer concept.
- Evidence-backed candidate verification.
- Product innovation and future direction.

## 2. Lakshay Kumar

### Role

**AI/ML, Voice, and Model Integration Engineer**

Lakshay owns the AI model layer and voice pipeline used to generate interview content, understand candidate responses, and conduct the AI-led Viva.

### Main Responsibilities

- Integrate the Qwen model hosted through Google Colab and FastAPI.
- Maintain the model API connection between Colab and the local Streamlit application.
- Manage API authentication, health checks, timeouts, and error handling.
- Design and improve prompts for:
  - Personalized question generation
  - Code walkthrough questions
  - Debugging questions
  - Architecture and trade-off questions
  - Behavioral questions
  - Follow-up questions
  - Spoken-answer evaluation
- Ensure questions are based on the candidate’s actual resume, projects, skills, and repositories.
- Maintain response parsing for structured JSON generated by the model.
- Prevent invalid model output from crashing the application.
- Integrate Whisper speech-to-text.
- Integrate text-to-speech for AI interviewer prompts and responses.
- Tune model generation settings for latency and quality.
- Investigate slow Colab responses and remote model failures.
- Ensure the system never silently replaces real AI behavior with fixed demo questions.

### Key Deliverables

- Working Colab model server.
- FastAPI `/health` endpoint.
- FastAPI `/generate` endpoint.
- Secure API key configuration.
- AI question-generation prompts.
- Answer-evaluation prompts.
- Voice transcription pipeline.
- Text-to-speech pipeline.
- Remote model timeout and error handling.
- Model integration test results.

### Areas of Ownership

- Qwen model integration.
- Prompt engineering.
- AI response validation.
- Whisper integration.
- Text-to-speech.
- Adaptive Viva behavior.
- AI service monitoring and reliability.

### Collaboration

- Works with Prakarsh on interview strategy and AI architecture.
- Works with Om on AI speaking/listening states and voice interaction UI.
- Works with Titiksha on API configuration, test isolation, and deployment setup.

### Presentation Responsibility

Lakshay presents:

- How the AI model works.
- How the Colab model connects to the application.
- How prompts are personalized.
- How Whisper and text-to-speech support the Viva.
- How AI errors, timeouts, and invalid outputs are handled.

## Shared Team Responsibilities

Although each member has a primary ownership area, all members should:

- Review changes that affect their area.
- Keep secrets out of source control.
- Test the complete user flow before demonstrations.
- Report limitations honestly.
- Maintain clear communication about breaking changes.
- Support the final presentation and live demo.
- Avoid claiming features that are not implemented or verified.

## Suggested Integration Workflow

1. Prakarsh defines the feature requirement and acceptance behavior.
2. Lakshay implements or validates the AI/model behavior when AI is involved.
3. Titiksha connects the feature to persistent data and tests it.
4. Om presents the feature clearly in the user interface.
5. The full team validates the end-to-end flow.
